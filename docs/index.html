apply-scout

An LLM agent that matches a job posting against a candidate's CV and GitHub evidence, then drafts a match report and a grounded cover letter — a tool loop written from scratch, with safety budgets and a trajectory-evaluation harness.

Evaluation: when is the cheaper model enough?

The harness runs each model end-to-end over the task set and records every metric from the logged trajectory. Cost is measured through a single token-accounting helper, not estimated.

On this task set the strong model costs roughly seven times more per task while scoring no better: identical completion and citation fidelity, and a marginally lower requirement-F1. For extracting and matching postings at this scale the inexpensive model is the better default. Requirement-F1 is an exact set match after case-folding, so it should be read as a strict lower bound on extraction quality rather than a failure to read the posting.

Architecture: a tool loop written from scratch

  • An explicit control loop, not a framework. Full control over the control flow is what makes safety budgets, the trajectory log, and systematic evaluation possible.
  • Safety budgets. Every run is bounded by maximum steps, tokens, and cost; exceeding a ceiling is a controlled stop with a partial report, never a crash.
  • A trajectory for every run. Each model call, tool call, and its cost is logged as JSONL — the substrate the evaluation harness reads.
  • Evidence or nothing. Every claim must trace to a real, checkable link; a cover-letter sentence citing a link absent from the report is removed by the guardrail, and the gap is reported rather than hidden.
  • Dependency injection throughout. Every component depends only on injected collaborators, so the whole system runs under scripted fakes with no network and no API key.

Limitations

Stated plainly, because an agent that hides its failure modes is worse than one that names them:

  • Postings are fetched as static HTML; a client-rendered, JavaScript-only page yields little readable text, so requirements extracted from such a page are unreliable.
  • GitHub evidence is drawn from repository metadata and README text, not full code search; a skill demonstrated only deep in a source file is honestly rated as unsupported.
  • The guardrail bounds hallucinated citations, not every possible overstatement; it checks that a cited link exists in the report, not the truth of a grounded claim.
  • No application is ever submitted. apply-scout drafts a report and a letter for a human to review and send; it does not act on the candidate's behalf.
